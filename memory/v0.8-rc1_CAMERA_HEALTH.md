## Livré maintenant

### 1. Camera Health Score (feature bonus P2 du mandat)

Nouveau module `backend/services/camera_health.py` (170 lignes) qui
calcule un score 0-100 par caméra à partir de 7 signaux pondérés :

| Signal | Poids | Source |
|--------|:-:|--------|
| **FPS réel vs attendu** | 25 % | `inspector.snapshot()` + `cam.target_fps` |
| **Fiabilité pipeline** | 20 % | ratio errors / calls sur les 300 samples inspector |
| **Qualité OCR (60 dernières plaques)** | 15 % | `db.plates.confidence` moyenne |
| **Fiabilité RTSP** | 15 % | `frame_source.status().last_frame_ts` |
| **Latence p95 vs SLA 200 ms** | 10 % | `max(stages.p95_60s)` |
| **Fraîcheur ONVIF** | 10 % | `cam.onvif_last_seen` / `updated_at` |
| **Fraîcheur événements** | 5 % | `db.events.timestamp` le plus récent |

**Bands** : `healthy` ≥ 80, `degraded` ≥ 55, `critical` < 55.

Retour :

```json
{
  "camera_id": "demo-cam-002",
  "score": 61.1,
  "band": "degraded",
  "signals": {
    "fps": {"pct": 0.0, "weight": 25.0, "hint": "réel 0.0 / attendu 10"},
    "pipeline_reliability": {"pct": 100.0, "weight": 20.0, "hint": "0 err / 1 calls"},
    "ocr_quality": {"pct": 47.1, "weight": 15.0, "hint": "conf moy. 47% sur 60 plaques"},
    "rtsp": {"pct": 100.0, "weight": 15.0, "hint": "worker non actif"},
    "latency_p95": {"pct": 100.0, "weight": 10.0, "hint": "p95 max 0ms (SLA 200)"},
    "onvif_freshness": {"pct": 40.0, "weight": 10.0, "hint": "pas d'heartbeat ONVIF"},
    "event_freshness": {"pct": 100.0, "weight": 5.0, "hint": "dernier évt il y a 0 min"}
  },
  "reasons": ["fps: réel 0.0 / attendu 10", "onvif_freshness: pas d'heartbeat ONVIF"]
}
```

**Endpoints** :
- `GET /api/cameras/{camera_id}/health` — une caméra
- `GET /api/cameras/health` — toutes + résumé `{total, healthy, degraded, critical}`

Preuve live preview : `summary: {total: 2, healthy: 0, degraded: 1, critical: 1}`.
L'intégrateur voit **immédiatement** quelles caméras nécessitent une
intervention.

### 2. Camera Capabilities Matrix (P1 du mandat — endpoint seul)

Nouveau `GET /api/cameras/capabilities-matrix` — agrège les
`capabilities` déjà collectées par chaque driver (v0.7.c/d) sous forme
de matrice vendor × capability :

```json
{
  "rows": [
    {"camera_id": "…", "vendor": "hikvision", "model": "…",
     "capabilities": {"ptz": true, "audio_input": true, ...}}
  ],
  "capability_keys": ["audio_input", "audio_output", "onboard_ai",
                      "ptz", "ptz_presets", "codec_h265", ...],
  "vendor_summary": {
    "hikvision": {"count": 3, "caps_present": {"ptz": 3, "audio_input": 2}, "caps_total": 22}
  }
}
```

L'UI (à venir dans une vague dédiée frontend) peut afficher un tableau
✓/✗ complet avec ligne récapitulative par constructeur. Backend prêt.

## Recommandation

Le **produit MG-VMS a aujourd'hui les briques d'un vrai VMS
professionnel** : hot reload chirurgical, pipeline instrumenté avec
percentiles, cache OCR intelligent, fusion pondérée, gate qualité crop,
alertes QoS automatiques, HTTPS/TLS complet, ErrorBoundary global,
Camera Health Score.

Pour un **client pilote**, il est déjà déployable si :
1. GPU présent (les extrapolations Wave F confirment < 200 ms à 50 cams)
2. Les 17 indexes Mongo recommandés par l'audit sont créés
3. Un driver vendor spécifique est disponible (ONVIF Generic marche déjà)

Le passage v0.8 GA nécessitera les 12 sessions ci-dessus. Je recommande
d'attaquer d'abord **P8 (Ops Center Monitoring UI)** — c'est ce que
l'intégrateur voit en premier lors d'un site walkthrough.
